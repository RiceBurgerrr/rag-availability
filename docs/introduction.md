# Introduction (v10 — 팀 피드백 반영)

> v9 기준. 등록/런타임 2단계 구성 제거, 평가 문단 삭제, 공격 소개 3종으로 압축, 기여의 무게중심을 탐지에서 **복구**로 이동.

## 1. 서론

대형언어모델(Large Language Model, LLM)은 방대한 학습 데이터를 기반으로 다양한 질의에 응답할 수 있으나, 학습 시점 이후의 정보나 학습 데이터에 포함되지 않은 특정 도메인의 지식을 활용하는 데 한계가 있다. 검색 증강 생성(Retrieval-Augmented Generation, RAG)은 사용자 질의와 관련된 정보를 외부 지식 저장소에서 검색하여 LLM의 입력 문맥에 포함시킴으로써 이러한 한계를 보완한다. 추가 학습 없이 최신 정보와 도메인 지식을 반영할 수 있고 검색된 정보를 근거로 제시하여 환각을 완화할 수 있어, 질의응답과 고객 지원을 비롯한 다양한 분야에 적용되고 있다.

그러나 RAG는 LLM 단독 시스템에 비해 추가적인 공격 표면을 형성한다. 시스템의 신뢰 경계가 사용자 질의와 생성 모델에 한정되지 않고 문서의 수집·저장·검색 및 입력 문맥 구성 과정까지 확장되기 때문이다. 신뢰하기 어려운 외부 문서를 색인하는 환경에서는 공격자가 통제하는 문서가 지식베이스에 포함될 수 있으며, 해당 문서가 특정 질의와 높은 관련성을 갖도록 구성되면 정상 문서와 함께 입력 문맥으로 전달되어 응답에 영향을 미친다. 공격자는 질의나 모델 파라미터를 직접 조작하지 않고도 검색 문서를 간접적인 입력 경로로 이용할 수 있으며, 해당 문서가 제거되기 전까지 반복적으로 영향을 미칠 수 있다.

이러한 공격 표면을 통해 발생하는 위협 중 하나는 정상 질의에 대한 응답 가용성을 침해하는 공격이다. 본 연구에서 다루는 가용성 침해는 자원 고갈로 시스템 전체를 중단시키는 전통적인 서비스 거부(Denial-of-Service, DoS)와 달리, **시스템이 실행 상태를 유지하면서도 정상적으로 답변할 수 있는 질의에 대해 답변을 거부하거나 실질적인 정보를 제공하지 않는 현상**을 의미한다. 즉 시스템은 요청을 수신하고 형식적인 출력도 반환하지만, 사용자가 요구한 질의응답 기능은 제공하지 못한다.

이러한 거부 응답은 정보가 부족한 질의를 처리하거나 안전 정책을 준수하는 과정에서도 자연스럽게 발생하므로, 출력만으로는 공격에 의해 유도된 거부와 정상적인 모델 동작을 구분하기 어렵다. 잘못된 사실을 생성하는 무결성 공격은 기준 정답이나 외부 근거와 대조하여 이상 여부를 평가할 수 있으나, **거부 응답은 검증 대상이 되는 사실 명제를 거의 포함하지 않으므로 사실성 중심의 평가로는 공격 여부를 판별할 수 없다.** 그 결과 거부가 드러나더라도 그 원인이 질의의 부적절성, 검색 정보의 부족, 모델의 정상적인 안전 정책, 오염된 검색 문서 중 무엇인지 식별하기 어려우며, 이는 공격의 탐지뿐 아니라 원인 문서의 식별까지 어렵게 만든다.

가용성 공격은 다수 질의의 응답을 광범위하게 방해할 수 있을 뿐 아니라, 공격자가 노출을 억제하려는 특정 주제의 응답만을 선택적으로 차단하는 데에도 악용될 수 있다. 예컨대 제품 지원 챗봇의 지식베이스가 오염되면, 사용자가 특정 제품의 결함이나 환불 조건을 문의할 때만 답변을 거부하도록 유도할 수 있다. 다른 문의에는 정상 응답하므로 시스템 장애로 인식되지 않지만, 해당 정보에 접근하려는 사용자에게는 서비스의 핵심 기능이 차단된다. 지금까지 RAG 보안 연구는 주로 무결성 침해를 다루어, PoisonedRAG[1]와 같이 공격자가 지정한 답변을 유도하는 지식 오염에 초점을 맞추어 왔다. 이와 구분되는 가용성 공격으로 두 가지가 제시되었다. Jamming[2]은 특정 질의에 대해 상위로 검색되도록 설계된 blocker 문서를 삽입하여, 정상 근거가 함께 검색되더라도 시스템이 정보 부족이나 안전상의 이유를 제시하며 응답을 거부하도록 유도한다. MutedRAG[3]는 **LLM의 안전 가드레일 자체를 공격 수단으로 역이용한다.** 지식베이스에 유해 질문에 해당하는 jailbreak 텍스트를 삽입하여, 해당 텍스트가 검색 문맥에 포함되었을 때 모델이 자신의 안전 정책을 발동시켜 무관한 정상 질의까지 거부하게 만든다.

이러한 공격이 성립하는 배경에는 기존 안전장치의 검사 범위가 있다. 실무에서 널리 사용되는 프롬프트 가드레일은 대체로 사용자 질의 또는 최종 응답에 나타나는 유해 콘텐츠 패턴을 탐지하도록 설계되어, **검색된 컨텍스트 내부에 삽입된 텍스트 자체를 검사 대상으로 삼지 않는 경우가 많다.** 즉 RAG의 보안은 질의–응답 경계의 방어만으로 완결되지 않으며, 검색 결과가 입력 문맥으로 조립되는 구간에 별도의 방어 계층이 요구된다.

학술적으로 제안된 방어 연구는 악성 문서의 사전 탐지와 오염된 컨텍스트에 대한 강건한 생성에 초점을 두어 왔다. RobustRAG[4]는 검색 문서를 개별 격리 처리 후 집계하여 오염의 영향을 제한하고, RAGForensics[5]는 공격에 책임이 있는 오염 문서를 추적하며, RAGuard[6]는 검색 범위를 확장한 뒤 chunk 단위 perplexity와 유사도 필터링으로 오염 문서를 식별한다. 그러나 이들 접근은 두 가지 한계를 갖는다. 첫째, 문서를 단독으로 평가하므로 질의와 결합되었을 때 비로소 드러나는 위험을 포착하지 못하며, 알려진 패턴을 회피하도록 작성된 문서를 놓칠 수 있다. 둘째, **의심 문서를 배제하거나 그 비율을 낮출 뿐 배제된 근거를 대체하지 않는다.** 근거가 줄어든 상태에서는 모델이 답변에 필요한 정보를 확보하지 못해 응답 실패가 유지될 수 있으며, 이는 무결성 관점의 성공이자 가용성 관점의 실패다. 확인한 범위에서는, 가용성 침해를 대상으로 후순위 근거를 이용한 응답 회복을 질의 단위로 평가한 연구는 제한적이다.

사전 탐지가 완전할 수 없다는 점을 전제로, 본 연구는 **검색 이후 생성 이전 구간에서 동작하는 런타임 방어**를 제안한다. 제안 방법은 검색된 각 청크를 질의와 결합한 상태로 평가하여, 질의 신호와 청크 신호의 곱으로 상호작용 항을 구성한다. 이 항은 질의 정보가 없는 문서 단독 평가로는 계산할 수 없으므로, 기존 입력 기반 탐지가 포착하지 못하는 질의 조건부 위험을 판정한다. 위험 신호로는 명령문의 표면 형태와 문맥의 자연성을 함께 사용하며, 두 신호는 서로 다른 공격 변종을 보완적으로 포착한다. 위험이 확인되면 해당 청크와 출처를 제외 목록에 누적한 뒤 동일 질의로 재검색하여 **검사를 통과하는 후순위 근거를 확보하고 응답 생성을 재시도한다.** 제외 집합의 단조 증가와 재검색 시도 상한이 절차의 종료를 보장하며, 대체 근거를 확보하지 못한 경우의 응답 보류는 방어가 유발한 실패로 별도 계측한다. 한편 질의 단독 위험이 검색 문맥에 의해 뒷받침되지 않으면 개입을 억제하여, 질의만을 근거로 검색 문맥을 제거하지 않도록 한다.

본 연구의 기여는 다음과 같다. **첫째**, 의심 근거의 배제에 그치지 않고 제외 목록 기반 재검색으로 후순위 근거를 재확보하여 응답 가능성을 유지하는 완화 절차를 설계하고, 절차의 종료와 최대 재검색 횟수를 보장한다. **둘째**, 질의와 청크가 결합된 시점에만 계산 가능한 상호작용 신호를 이용하여, 문서 단독 평가로는 계산할 수 없는 질의 조건부 위험을 판정하는 방법을 제안한다. **셋째**, 추가 LLM 호출 없이 동작하는 경량 신호 조합을 구성하고, 명령 표면 신호와 문맥 자연성 신호가 서로 다른 공격 변종을 보완적으로 포착함을 보인다. **넷째**, 탐지율이 아니라 **공격으로 실패한 전체 질의를 분모로 하는 응답 복구율**을 주 지표로 삼고 오탐률과 방어가 유발한 실패를 함께 계측하여, 가용성 공격에 대한 방어의 실효성과 부작용을 동시에 평가하는 실험 체계를 제시한다.

### 등록 단계 제거의 부수 효과 (개선)

v9는 "우리 등록 단계 vs 우리 런타임 단계"의 정보 차이로 질의 조건부 판정을 정당화했다. v10은 이를 **"기존 입력 기반 탐지(문서 단독 평가) vs 제안 방법(질의 조건부)"**의 대비로 바꾸었다.

같은 논거가 내부 구성 설명이 아니라 **선행 연구와의 차별점**이 되므로 포지셔닝이 강해진다. RAGuard의 chunk 단위 perplexity 필터링이 전형적인 문서 단독 평가에 해당하므로, 6문단의 첫 번째 한계 서술과 직접 연결된다.

### 기여 무게중심 이동

| | v9 | v10 |
|---|---|---|
| 1 | 경량 탐지기 | **후순위 근거 재확보 (복구)** |
| 2 | 질의 조건부 판정 | 질의 조건부 판정 |
| 3 | 단계적 정화 | 경량 신호 조합·상보성 |
| 4 | 평가 체계 | 평가 체계 |

팀 피드백의 *"기존 탐지 방법은 규칙기반 성격이 강해 핵심으로 제안하기엔 부족하다"* 는 지적은, 기여의 중심이 탐지에 놓여 있을 때 성립한다. 신규성의 근거인 gap(§6문단: 배제만 하고 대체하지 않음)이 복구에 있으므로 중심을 옮기면 해당 지적의 상당 부분이 해소된다.

## 제출 전 확인 사항

1. **문맥 자연성(perplexity) 신호는 현재 미구현이다.** 7문단과 기여 3의 근거이므로 구현을 전제로 작성했다. 구현하지 않을 경우 해당 서술을 삭제하고 기여 3을 재작성해야 한다.

2. **등록 단계의 논문 내 위치.** 서론에서는 제외했으나 시스템에는 존재한다. 실험 절에서 baseline 계층으로 등장시킬지, 아예 비활성화하고 런타임 단독으로 평가할지 결정이 필요하다. 후자가 논지에 더 부합한다.

3. **"3-Way Cleansing" 명칭 미사용.** 코드가 `allow / requery / remove / block` 4단계로 분기하므로 v10은 명칭 없이 동작만 기술했다. 명칭을 살리려면 3단계로 묶는 근거를 방법론 절에서 제시해야 한다.

4. **"의미 전환 분석"(문서 전·후반부 비교)** — 「논문 서론」 초안에 기여로 포함되었으나 코드 확인 범위에서 발견하지 못했다. 구현 여부 확인 후 기여 3에 추가 가능하다.
